### 3.6.2 Adjudication Data Storage

Adjudication uses two folders inside the project folder. Keeping them separate means regular annotation
files stay clean and standard, while the adjudication working state lives on its own.

| Folder | Contains | Purpose |
|---|---|---|
| `saved/` | `<annotation>` elements only | Regular annotations from each annotator |
| `adjudication/` | `<annotation>` elements (the accepted, adjudicated result) plus `<adjudicating>` elements (items still needing review) | Adjudication working state and gold standard |

The `adjudication/` folder is written only when you save **while in adjudication mode**. This is why
eHOST prompts you to save before leaving adjudication mode (see
[3.6 Adjudication Mode](https://github.com/chrisleng/ehost/wiki/3.6-Adjudication-Mode)).

#### What gets written

Each annotation carries an adjudication status. Only unresolved items are stored as `<adjudicating>`
working copies:

| Status | Saved as `<annotation>` | Saved as `<adjudicating>` |
|---|---|---|
| Matched and accepted | Yes | No |
| Matched and deleted | No | No |
| Non-matching (needs review) | No | Yes |
| Not yet processed | No | Yes |

Resolved items do not need a working copy, because the accepted annotation is already stored as a
regular `<annotation>` and the discarded duplicates can be recovered by comparing the `adjudication/`
and `saved/` folders. Skipping them typically removes 70-80% of the adjudication file content and makes
loading and saving large projects noticeably faster.

#### Backward compatibility

Adjudication files produced by older eHOST versions - or files that were edited by hand - may not
contain any `<adjudicating>` elements. When eHOST loads a file from the `adjudication/` folder that has
annotations but no working copies, it recreates the working copies in memory automatically and marks
them as matched, so the annotations display and can be resumed as usual. Nothing needs to be done
manually; the next save writes the file in the current format.

#### Note on shared projects

Because the `adjudication/` folder is the single source of truth for adjudication state, copying or
archiving it is enough to preserve or transfer adjudication work. Deleting its `.knowtator.xml` files
makes eHOST treat the project as never adjudicated.
